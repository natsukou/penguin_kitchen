# G1 电子秤放置 ACT 评估与重训计划

## 任务范围与当前结论

第一版将任务定义为「右手已可靠持物 → 接近秤盘 → 稳定放置 → 松开 → 撤离」。先在已标定的工位上验证一种物体和一种右夹爪。把抓取、换手、多物体选择和双臂协同作为单独的任务范围。现场入口需确认右手确实持有目标、秤盘位置可用、当前姿态在已验证的起始范围内。

`act_take01_scale_23d.ckpt` 在两份 G1 快照上通过推理检查。它使用 1 条示教训练 1000 步，输入四路 `128 × 224` RGB 和 23 维状态，输出 100 步位置目标。两份快照只用于检查模型和接口，放置成功率仍待闭环实测。[复测说明](act-take01-test.md) · [原始报告](../artifacts/act-take01-test/cuda-fp32.json)

- **左臂回到示教姿态。** 两份快照的左臂目标与训练均值最大偏差小于 `0.0008 rad`。电子秤快照的左臂最大首步变化为 `1.31 rad`。静止自由度参与动作回归后，当前姿态偏离示教时也会收到回位目标。
- **右臂首步衔接有问题。** 电子秤快照中，`right_arm_joint5` 首步变化 `2.15 rad`，之后右臂相邻目标最大只差 `0.037 rad`。MuJoCo 静态投影的首步法兰位移约 `0.70 m`。首步与当前姿态的差需要独立评估。
- **夹爪输出越界。** 两份快照分别有 71 和 66 个负开口目标，最低约 `−15.6 mm`。单条示教的右夹爪重建 MAE 为 `10.2 mm`，需分别检查持续夹持和释放时序。头部也出现轻微超出参考 URDF 下限的目标。
- **预处理和标签仍需对拍。** 复测采用面积插值缩放，原训练 resize 实现待核对。本地转换器已把下一帧状态写入当前帧的 `action`，是否发生二次移位要检查原训练 loader。右臂首步跳变目前不能归因于某一种实现错误。[转换器](../external/galbot-mcap2lerobot/src/galbot_mcap2lerobot/galbot_mcap_to_lerobot.py#L627)

## 评估计划

### E0 对拍原训练数据与推理接口

负责人为数据和训练同学。取回 `take01_v21` 的四路视频、Parquet、元数据、原训练 loader 和预处理配置。抽查起始、接近、释放及末尾，并对齐下面几项。

1. 对照四路视频帧号和时间戳、相机顺序、RGB 通道、resize 插值、归一化和遮挡情况。选一组黄金样本保存四路预处理张量、归一化前后的状态和模型输出，用同一 FP32 输入比较原训练入口与复测入口。
2. 逐维核对关节名、顺序、符号和单位。关节角用 rad，夹爪开口用 m。同步记录原始观测和命令时间，测量每路相机与关节的偏差及 P95。按实际采样周期与运动速度定有效窗口；现有 `50 ms` 是快照复测的判定窗口。
3. 验证每条 chunk 的第一步与对应帧的 `action[t]` 一致，序列不跨 episode，尾部填充不进入损失和评估。同步保留控制器位置目标与实测位置，记录 `action_source`。已有 next-state 数据采用 `q[t+1]`，新增数据优先用对应控制时刻的遥操作目标，两个标签来源分开统计。

通过条件为黄金样本逐字段、逐帧一致，且原入口与复测入口的输出差异能用预先约定的浮点容差解释。若原始资产缺失，沿用当前结果作为接口基线，并用新采样本建立可复现对拍。

### E1 留出示教的开环评估

所有候选使用同一份数据版本和同一组窗口。ACT 使用 `z=0` 做推理。对比保持当前位置的基线、旧 checkpoint 和重训版本。在 8 维公共通道比较，同时保留旧模型的全身越界记录。先用验证集选模型，锁定版本后再跑留出集。[ACT 论文与推理说明](https://arxiv.org/html/2304.13705#S4)

- **跟踪误差**。按关节和阶段报告首步 MAE，以及约 `0.2 s`、`0.5 s`、`1 s` 处的误差。窗口超出轨迹时掩码，不在动作块内的时刻标为未覆盖；模型之间比较共同覆盖的时刻。按 episode 汇总并给出 P50、P95、最大值。对持物和释放阶段分开报夹爪误差，单位为 mm。
- **首步与连续性**。记录 `|a[0]−q[t]|` 和相邻目标差，按实际周期换算目标速度。用标定后的关节、夹爪、速度与加速度约束检查原始目标，同时记录投影后的法兰位移。结果按起始姿态、秤位置和任务阶段分层。
- **释放事件**。将第一次有效开夹与标注的 `release_allowed` 时刻对齐，报告提前释放率、漏释放率和释放延迟。近阈值样本保留原始宽度和标注依据，便于复查。
- **推理周期**。记录从观测到候选目标的 P50、P95、P99、缺帧率和超时率。将模型前向、图像处理、校验耗时分开记录，用端到端 P99 对照重规划周期。现有 GPU 的 `25–27 ms` 只计模型前向。

晋级条件为候选在移动和释放窗口优于保持当前位置，且首步跳变、释放错误和越界数量优于旧模型。进入后续闭环的候选须在已定义工况下满足物理边界和首步限制。首步限制按实际更新周期、标定速度和现场接近约束确定，评估前固定。原始预测与控制检查结果分别保存，保留被拒绝的原因。

### E2 静态检查、闭环仿真与实机试验

1. **影子运行**。实时读取观测并生成候选，不发运动命令。记录初始偏差、轨迹碰撞检查、预测超时与失效处理。注入缺相机、旧帧、秤移动、目标丢失和越界，预期进入保持或停止并记录原因。静态运动学只用于位姿和约束筛查。
2. **闭环仿真**。使用具备桌面、秤盘、物体和夹爪接触模型的场景，按最新观测滚动重规划。分别测试常规起点、边界起点、可恢复偏差和超出训练范围的输入。每次只执行动作块前少量步，刷新观测后继续；比较 1 步和 3 步重规划，按端到端耗时选周期。释放由状态机核对物体已受秤盘支撑，再批准夹爪打开。动作候选通过首步、限位、速度和碰撞检查后由控制器下发。
3. **实机分级试验**。先核对停止通道和速度限制，做空夹爪低速路径；再用试件验证持物、接触、释放和撤离，最后用固定的条件矩阵做正式试验。独立保存每次任务结果。碰撞、掉落或提前释放时停止该批次，复盘原始观测和动作后重测。

**单次成功定义**为物体受秤盘支撑，夹爪释放后物体连续稳定至少 `2 s`，且右臂撤离时未碰到秤盘或物体。`2 s` 是首版建议值，可按电子秤的稳定判定标定。若秤有可读数值，记录去皮、稳定质量和时间，作为辅助证据。每次运行标注 `success`、`safe_hold` 或 `failure`。域内试验中的暂停计入总数，故障注入另外报告正确拦截率。报告成功次数、总数、分工况结果和区间估计。首轮可用 `30` 次正式试验、至少 `27` 次成功作为内部试点目标，并要求零碰撞、零掉落和零提前释放。达到试点目标后再扩大工况和样本量。

## 数据采集与训练调整

### 数据组织

- 第一批建议 `50` 条训练、`10` 条验证、`10` 条留出示教。分多个采集场次，按 `session_id` 切分，确保同一次录制、切片和近重复片段留在同一集合。留出集提前锁定，由独立场次覆盖常规与边界工况。这些数量是初版采集预算，后续按阶段失败率扩采。
- 采集矩阵覆盖右臂起始关节姿态、物体持握角度、秤盘位置、光照与合理遮挡。保留接近过程的小偏差和回正片段。失败演示记录故障和恢复的时间点，成功动作训练使用有明确专家动作的片段；掉落或误释放的行为用于失败分析和拦截测试。
- 原始记录保留四路图像及时间戳、关节反馈、遥操作目标、夹爪宽度与反馈、相机与夹爪标定版本、场景 ID、物体 ID、秤盘位姿或绑定引用、事件和结果。训练归一化只用训练集，固化字段顺序、单位、帧率、预处理版本和数据哈希。

### 训练实验顺序

1. **复现基线**。冻结旧 checkpoint，在新留出数据的公共通道上评估。用多轨迹训练一个同结构 23 维对照，保持相机和 chunk 配置，用来观察单轨迹覆盖与输出维度分别带来的差异。23 维对照只参与离线评估。
2. **首选候选**。保留四路 RGB 和全身状态输入，输出右臂 7 个关节位置加右夹爪宽度，共 8 维。其他部位由原有控制器保持。先在同样的标签与损失下比较 23 维和 8 维绝对目标，再给 8 维候选增加夹爪有界输出头。夹爪标签映射到标定有效区间，评估时报告实际 mm 误差。采用掩码 L1，分开记录手臂和夹爪损失；若漏释放集中在短窗口，再提高释放片段的采样比例。先用原版 `128 × 224` 和 ResNet18 以控制变量。
3. **验证首步和时间范围**。若绝对目标的首步仍不连续，对照以 `q[t]` 为锚点预测右臂相对位移，推理时还原为绝对目标。先固定 `K=100` 比较输出设计，再扫 `K=20/50/100`。若数据为 `30 Hz`，分别约 `0.67/1.67/3.33 s`。观察长窗口是否覆盖放置阶段，短窗口是否改善反应。各候选使用同一重规划设定对比，再调整执行步数。
4. **优化与选择**。起跑沿用模型学习率 `1e-4`、视觉骨干 `1e-5`、`KL=10`，先固定有效 batch 和随机种子。初始训练预算可设 `10k` 更新，每 `500` 步做一次验证，连续 5 次未改善则停止。入围方案再用 3 个随机种子复训；以验证集的首步连续性、释放和越界指标选候选。只有当证据指向看不清秤沿或目标时，再单独比较更高分辨率。只有观察到多次训练的先验推理表现和训练重建明显分离时，再做 KL 对照。

每个版本记录模型哈希、数据拆分、随机种子、动作定义、预处理、训练与推理参数。交付物为 checkpoint、归一化统计、离线回放报告和闭环试验记录。先交付 E0 对拍，再交付训练数据清单和 E1 对照结果，最后交付 E2 验收记录。

## 文本信息规划

把操作员指令、训练标注和评估记录分开存储，通过 `task_id`、`episode_id` 或 `run_id` 对齐。第一版用文本选定技能和目标，ACT 保持四路图像加关节状态输入。只有在同一场景需要按语言在多个目的地或动作中做选择、且已有成对示教数据时，再评估给 ACT 增加语言条件。

### 操作员指令与场景绑定

当前 G1 `TaskRequest` 支持抓取、取放和摇后放回，现有文本解析器只接通瓶子任务和原位类目的地。下方 `place_on_scale`、`destination_id` 和右臂路由为拟新增契约。复用现有文本解析和目标消歧入口，在进入动作阶段前增加秤盘 ID 与右手持物校验。[现有控制中枢说明](control-center.md)

- `text` 保留用户原话，便于复查。
- `intent` 使用固定词表 `place_on_scale`、`hold`，其他意图由已有技能处理。
- `object_ref` 和 `destination_ref` 保留「右手里的物体」「电子秤」等解析出的指代。
- `arm`、`object_id` 和 `destination_id` 来自场景绑定。确认右手持有该物体、秤盘已定位且符合当前任务范围。
- `scene_revision`、`status` 和 `reason` 记录绑定时的场景版本、处理结论和原因。

例如「把右手里的碗放到电子秤上」绑定为右臂、当前已持有的碗和已识别的 `scale_01`。「放到那边的秤上」在存在两台秤且无法定位指代时返回 `needs_clarification`。「先别松手」映射为 `hold` 并交给状态机处理。`object_id`、`destination_id` 和位姿由观测绑定，文本解析只产生意图与指代。

一条示例绑定记录如下，`resolved` 表示语义和场景绑定完成，运动检查使用后续状态。

```json
{
  "task_id": "scale_task_001",
  "text": "把右手里的碗放到电子秤上",
  "intent": "place_on_scale",
  "object_ref": "右手里的碗",
  "destination_ref": "电子秤",
  "arm": "right",
  "object_id": "bowl_01",
  "destination_id": "scale_01",
  "scene_revision": "scene_001",
  "status": "resolved"
}
```

### 示教标注与训练语料

每条示教在 episode 元数据写入 `task_id`、`instruction`、`object_id`、`destination_id`、`arm`、`session_id`、`action_source`、`outcome`。阶段边界用帧号或统一时间戳记录，建议使用 `carry`、`approach`、`place_contact`、`release`、`retreat`。独立标注 `support_confirmed`、`release_allowed`、`gripper_opened`、`object_stable` 和 `retreat_done`，便于计算释放提前量与成功率。未来事件只用于监督和评分，运行时阶段依据当前可观测证据更新。

中文解析语料复用现有 JSONL 结构 `group`、`text`、`intent`、`slots`，为放秤任务增加 `destination` 和持物指代的测试。首批覆盖同义表达、口语与听写变体、目标歧义、否定和暂停、多指令、超范围目的地。按同义句组切分，减少模板泄漏。单独评估意图宏 F1、整句槽位完全匹配率、物体与秤盘绑定准确率，以及歧义和停止指令的错误放行次数。歧义与停止用例的错误放行为零，作为首版文本验收门槛。

### 操作员反馈与评估文本

操作面板用同一套状态词显示「已识别任务」「正在接近秤盘」「已确认支撑」「已释放」「已撤离」「暂停待确认」。只有传感器或人工标注提供对应证据时，才进入已确认状态。失败消息写清当前阶段、触发条件和下一步，例如「接近阶段暂停。秤盘定位已过期，请更新场景后重试。」

每次报告保存 `run_id`、`task_id`、模型版本、数据版本、场景、阶段、原始动作摘要、约束结果、释放事件时间、`outcome` 与 `reason_code`。统一失败原因如 `FIRST_STEP_JUMP`、`GRIPPER_RANGE`、`EARLY_RELEASE`、`TARGET_AMBIGUOUS`、`OBSERVATION_STALE`、`CONTACT_UNCONFIRMED`。按失败原因回收示教，优先补充出现频率最高且对成功率影响最大的工况。
